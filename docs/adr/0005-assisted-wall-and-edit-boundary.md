# ADR 0005：受控单墙候选与独立 BIM 工具回读

状态：2026-11-13 **局部实现，实验性**；不批准 V0.2 发布或改变 Core 契约。

## 问题和决定

用户需要能从现场证据得到并修改模型。单纯的点云或图片渲染无法提供构件语义和可追溯参数；同时，要求全自动和完整房间会阻塞可用能力。因此先支持一块可见墙，使用人工选区、明确尺度来源和厚度假设，计算具有属性级证据的 `parametric-ir/0.2` 并生成 IFC4 `IfcWall`。提供 RGB-D 传感器辅助模式及真实公制点云的自动几何候选；前者用参照实际求尺度，后者使用数据发布方明确声明的米制坐标。用户确认、模型推断和假设必须分别标记，不给不可见墙体、开口和实际厚度制造观测。

墙体导出包含 IFC 轴线和 `IfcMaterialLayerSetUsage`，使外部 BIM 应用可通过墙长工具重新生成实体。材料名称为 `Unspecified material`，材料与厚度是否为观测由 IR 证据状态决定。GUID 根据项目和构件 ID 稳定生成，而不是根据尺寸生成。

外部 IFC 只允许将一个经验证的墙长修改同步回 IR：校验 IFC4 类型、构件 ID/GUID、轴线、墙位置、单层厚度、矩形挤出及高度；保留外部文件 SHA-256，生成新的模型版本并标记须重验。其他外部修改拒绝同步；通用 BIM 导入、尺寸冲突处理、拓扑与多构件增量更新仍是规划。以上均位于产品目录，Core 与 Harness 保持分离。

## 证据与后果

- 旧 IFC 未提供墙轴线和层，Bonsai 墙长工具报错；网格修改可保存但会丢失拉伸参数。
- 增加轴线和层之后，Bonsai 0.9.0.post1 将真实照片草稿的墙长从约 0.428 改至 0.500 m 并保存，仍为挤出实体；web-ifc 与 IfcOpenShell 独立读回且 GUID 保持。单墙长度同步已实测。
- 这验证了有限编辑工作流，**没有证明墙尺寸的真实准确性，也没有证明多墙、门窗、CAD 约束或本体模型可用于工程**。本例锚点来自同一深度传感器；真实独立尺寸和用户成本仍缺失。
- CRASLAB 的点云几何先验误将大量白板归为墙，必须保留推断状态，且不得将本轮结果当成已验证的语义分割。IFC 参考模型与点云坐标系尚未配准。

按照 [WS-RealRoom 冻结门槛](../../benchmarks/ws_realroom/PROTOCOL.md)，只有独立真实场景、尺寸、构件覆盖和人力成本等结果全部通过后才能考虑发布。
